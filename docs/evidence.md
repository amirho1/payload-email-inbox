## Coverage details

Concurrent authenticated duplicate ingress creates one durable receipt/message/attachment set. Parallel queue clicks and workers submit once. Tests cover key rotation, tampering, malformed IDs, routing, size/decompression bounds, Unicode raw/processed MIME, quoted names, attachments, CRLF, From allowlists, Bcc privacy, notes, legitimate replies, forged/new-participant headers, cross-mailbox IDs/downloads/Local API and REST denial, HTML/XSS/tracker isolation, out-of-order/replayed events, terminal precedence, definite retry bounds, receipt-lease recovery, stale submission ambiguity and no resend.

Browser journeys sign in through Payload and exercise the real database/provider endpoints, safe HTML/attachments, durable draft/reply, captured MIME, customer reply continuity, rapid clicks, delayed/bounced states, compose/upload/reply-all/forward/failure retry/unknown actions, en/fa, 320/390/768/1440 widths, keyboard focus and axe checks, including dark mode. Screenshots in docs/screenshots contain synthetic data only.

## Measurements

See measurements.json for exact hardware/dataset/concurrency and current results. Budgets were set before implementation in progress.md. On Apple M2 Pro / 16 GiB / Node 22.23.4, the measured inbox p95 is approximately 12 ms for 1,000 conversations at concurrency 5; all 100 synthetic receipts were durably acknowledged in under 9 ms each at concurrency 5. RSS varies by process/run; recorded delta is below the 50 MiB budget. These are local measurements, not production guarantees.

Host same-base production builds: 1,513,150 → 1,519,490 bytes gzip across client JS files, **+6,340 bytes**. Compiled CSS added approximately 4 KiB. Package artifact is approximately 41 KiB compressed; exact final metadata is recorded at handoff. Four direct runtime dependencies, no additional runtime process or Redis requirement. The Moftkhar integration reuses its existing Redis and worker.

## Material limits

- Only Node 22.23.4 / Payload-UI-SQLite 3.90.2 / Next 16.3.3 / React 19.2.6 is tested. No PostgreSQL/MongoDB claim.
- Production must use a shared admission limiter and proxy byte/concurrency limits. Generic hosts supply a hook; Moftkhar's implementation uses existing Redis with real concurrency tests.
- Small private DB attachments have base64 overhead. No scanner is claimed without a hook; no large-file streaming or automatic orphan-byte reclamation is implemented.
- Retention defaults to dry-run, rechecks SQLite eligibility transactionally, skips pending/unknown work and threads over 100 messages, and retains shared attachment bytes. No silent data deletion on uninstall/rollback.
- No exactly-once SMTP or Inbox-placement guarantee. Unknown acceptance requires operator reconciliation.
- Production UI/language/access, deployment/image/route, controlled support/Gmail round trip and notification delivery remain unverified until the blocked rollout/owner checks are completed.
