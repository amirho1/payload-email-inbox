## Security and delivery evidence

Tests cover signature rotation/tampering, malformed headers and envelopes, bounded payloads/attachments, concurrent deduplication and atomic outbox claims, restart recovery, definitive rejection and unknown acceptance, terminal event precedence, forged/private threading, staff/mailbox permissions including Local API/downloads, From/CRLF/Bcc/notes, sanitized HTML and remote trackers, retention eligibility, disabled/config merging/collisions and public export installation. Additional inspection tests cover scoped legacy provider IDs, untrusted URLs, credentials/Bcc/header omission, bounded errors and safe management links.

Production signer trust was independently matched against authenticated server state. Readiness replay produced one durable message/attachment. Only the support route changed; other routing and notification identities were preserved. Established encrypted SQLite backups and isolated host restore rehearsal are recorded in progress.md. The production archive has not independently been decrypted/restored in this session.

## Material limits and unfinished release checks

- Final host checks/restore/build, commit/push/CI and intended production image identity remain to finish for alpha.5.
- Delivery-event webhook activation and recipient-observed notification regression remain pending. Provider acceptance alone is not recipient delivery.
- Only SQLite's atomic implementation is tested. Production admission needs a shared limiter; Moftkhar reuses its existing Redis and worker.
- Small private DB attachments have base64 overhead. Malware scanning requires a host hook; large-file streaming and automatic orphan-byte reclamation are absent.
- Retention defaults to dry-run, skips pending/unknown work and oversized threads, and preserves shared attachment bytes. Rollback/uninstall does not delete correspondence.
- Exactly-once SMTP and Inbox placement cannot be guaranteed. Unknown submissions never automatically resend.
- Host dependency findings and security compatibility changes are reviewed separately in the private integration repository; zero plugin advisories does not certify every unrelated host dependency.
